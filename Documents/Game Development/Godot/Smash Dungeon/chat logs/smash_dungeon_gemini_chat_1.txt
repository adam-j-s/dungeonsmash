Okay, you've encountered a common syntax limitation in GDScript.

The Problem:

GDScript does not allow you to define a standard named function (func function_name():) inside another function. The parser interprets this as an attempt to create a "standalone lambda" without assigning it, hence the error message.

While GDScript does have lambda functions (anonymous functions), they need to be assigned to a variable like this:

var my_lambda = func(arg1, arg2):
    # lambda body
    return result
# And called like:
my_lambda.call(value1, value2)
Use code with caution.
Gdscript
Your get_nested_value function is defined using the standard func keyword directly within _add_weapon_data_params, which isn't allowed.

Solution:

You have two main ways to fix this:

Make get_nested_value a method of your class: This is generally the cleanest and most standard approach in GDScript, especially if the helper function might be useful elsewhere in the script.

(Less Recommended for this case) Turn get_nested_value into a true lambda assigned to a variable: This keeps the code visually contained but requires using the .call() syntax.

Recommended Fix (Option 1: Make it a Class Method):

Move the get_nested_value function outside of _add_weapon_data_params so it becomes a regular method of your script/class. It's common practice to prefix helper methods like this with an underscore (_) to indicate they are primarily for internal use.

# Put this function at the class level (same indentation as _add_weapon_data_params)
# Helper to get nested data with fallback
func _get_nested_value(dict, path: String, default_value):
	var parts = path.split(".")
	var current = dict

	for part in parts:
		# Check if current is a dictionary before trying to access it
		if typeof(current) != TYPE_DICTIONARY or not current.has(part):
			return default_value
		current = current[part]

	return current

Important Observation:

Looking at your match statement, you are currently not using the get_nested_value helper function you defined. You are using weapon.weapon_data.get("key", default_value), which is the built-in dictionary method for getting a value with a fallback if the key doesn't exist. This works perfectly well for accessing top-level keys.

Therefore, the simplest fix is to just delete the func get_nested_value(...) definition entirely from inside _add_weapon_data_params.

You only need to implement _get_nested_value as a separate method (like in Option 1 above) if you actually intend to look up values using dot notation paths (e.g., "stats.damage.fire"), which your current code doesn't do.
