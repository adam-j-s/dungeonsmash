Now, as for behaviours, when it comes to it, will it be difficult to come up with lots and lots and lots and lots of options, and will that be difficult to put into script?

Edit
Creating a large variety of behaviors doesn't need to be difficult. The beauty of a well-designed behavior system is that once you've set up the foundation, adding new behaviors becomes relatively straightforward.

Here's how to approach it:

Starting Small But Expandable
Begin with core behaviors that already exist in your game:
Homing, bouncing, piercing, explosive, wave movement, etc.
Create a template for new behaviors that handles all the boilerplate code, so adding a new one just means filling in the unique logic.
Scaling Up Efficiently
As you expand, you can create behaviors in categories:

Movement behaviors: How the projectile travels
Homing, bouncing, gravity-affected, zigzag, spiral, returning
Impact behaviors: What happens when it hits
Explosive, piercing, splitting, freezing, burning
Duration behaviors: Effects over time
Lingering damage fields, DoT effects, temporary buffs/debuffs
Visual behaviors: How it looks
Trailing effects, color cycling, size pulsing
Making Implementation Easier
The key is to structure each behavior to:

Be self-contained
Have a clear interface with the rest of the system
Only worry about its specific effect
For example, a "split on impact" behavior would only need to:

Watch for collision events
Create multiple new projectiles when that happens
Configure those projectiles correctly
It doesn't need to understand how those new projectiles move or what they do when they hit something - other behaviors handle that.

Composition Is Powerful
The real magic comes from combining behaviors. You might only create 20-30 individual behaviors, but the combinations could be in the hundreds or thousands, giving you that "lots and lots of options" without needing to script each combination individually.

Does this approach align with what you're looking for?

Attack Styles vs. Behaviors
Level of Abstraction:

Implementation Timing:
Attack Styles: Execute at attack time to create the primary attack effect
Behaviors: Typically modify projectiles/effects after they're created
Combination:
Attack Styles: Mutually exclusive (can't be both melee and projectile simultaneously)
Behaviors: Designed to be combinable (homing + explosive + piercing)
Think of it like this:

Attack Styles are the "noun" - what the weapon fundamentally IS
Behaviors are the "adjectives" - qualities that modify how the weapon works
For example, a Singularity Bomb has the "singularity" attack style, but it also has "gravity", "explosive", and other behaviors that enhance that style.

The reason to separate them both into their own systems is to get the maximum organizational benefit and flexibility in your code structure.

func load_weapons_from_csv(file_path):
    if !FileAccess.file_exists(file_path):
        print("ERROR: Weapons CSV not found at: " + file_path)
        return false

    var file = FileAccess.open(file_path, FileAccess.READ)
    if !file:
        print("ERROR: Could not open weapons CSV file")
        return false

    # Read header row but don't process it as a weapon
    var headers = file.get_csv_line()

    # Extract the actual field names without descriptions
    var cleaned_headers = []
    for header in headers:
        # Extract just the field name before any space or parenthesis
        var clean_name = header.strip_edges().split(" ")[0].split("(")[0]
        cleaned_headers.append(clean_name)

    print("Processing CSV with fields: ", cleaned_headers)

    # Track which fields need array conversion
    var array_fields = ["effects", "special_flags", "behaviors"]

    # Track processed weapons for debugging
    var processed_count = 0

    # Read weapons
    while !file.eof_reached():
        var values = file.get_csv_line()
        if values.size() <= 1 or values[0].strip_edges() == "":
            continue  # Skip empty lines

        # Skip if not enough values
        if values.size() < 3:
            print("WARNING: Skipping incomplete weapon data: " + str(values))
            continue

        var weapon_data = {}

        # Process each field
        for i in range(min(cleaned_headers.size(), values.size())):
            var field_name = cleaned_headers[i]
            var value = values[i].strip_edges()

            # Skip empty fields
            if value == "":
                continue

            # Convert to appropriate type
            if field_name in ["damage", "tier"]:
                weapon_data[field_name] = int(value)
            elif field_name in ["attack_speed", "knockback_force", "projectile_speed", "projectile_lifetime"]:
                weapon_data[field_name] = float(value)
            elif field_name in ["attack_range_x", "attack_range_y"]:
                # Special case for attack range
                if !weapon_data.has("attack_range"):
                    weapon_data["attack_range"] = Vector2.ZERO
                if field_name == "attack_range_x":
                    weapon_data["attack_range"].x = float(value)
                else:
                    weapon_data["attack_range"].y = float(value)
            elif field_name in array_fields:
                # Split comma-separated lists into arrays
                if value.contains(","):
                    weapon_data[field_name] = value.split(",")
                else:
                    weapon_data[field_name] = [value] if value.length() > 0 else []
            else:
                # String values
                weapon_data[field_name] = value

        # Check if this is the first column with the weapon_id
        if values[0].strip_edges() != "" and cleaned_headers[0] == "weapon_id":
            weapon_data["weapon_id"] = values[0].strip_edges()

        # Skip if no ID
        if !weapon_data.has("weapon_id"):
            print("WARNING: Skipping weapon with no ID: ", values[0])
            continue

        # Store in weapons dictionary
        weapons[weapon_data["weapon_id"]] = weapon_data
        processed_count += 1

    print("Successfully processed " + str(processed_count) + " weapons from CSV")
    return true
